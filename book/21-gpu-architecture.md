# 第 21 章　GPU 的结构

从本章起是 GPU 路线。GPU 也是第 6 章抽象芯片的一个实例，但它对第 4 章"怎样隐藏延迟"这个问题给出了与静态调度相反的回答：在每个核心上同时驻留大量线程，一个在等存储，就换另一个执行。这让 GPU 能够容忍不可预测的延迟，也带来了它的编程模型：程序员写一个线程的程序，硬件把成千上万个线程编成组，以 SIMD 的方式执行。

近几代 GPU 又在这个基础上加入了几样新东西：直接从片上存储读取操作数的异步矩阵单元、按块搬运张量的专门引擎、专门存放累加结果的存储。现代 GPU kernel 的结构（第 23 章）正是围绕这些部件组织的。

本章自底向上地描述一颗 GPU：21.1 节给出全貌；21.2–21.4 节讲 SM 与它的线程调度、寄存器与共享内存、延迟隐藏与占用率；21.5、21.6 节讲 Tensor Core 的演变与异步搬运；21.7、21.8 节讲线程块簇与 GPU 之间的互联；21.9 节比较各代。

> **在体系中的位置**：下层是第一、二部分：矩阵单元（第 5 章）、存储与分体（第 3 章）、流水线与多线程（第 4 章）、芯片模型（第 6 章）、互联（第 7 章）、布局与交错（第 8 章）、异步与 mbarrier 的原型（第 9 章）。本章给出 SM 的组成、SIMT 执行、存储层次、占用率与 Little 定律、Tensor Core 与 TMA 的各代接口、簇与互联。第 22–27 章的编程模型与 kernel 都以本章为前提。

## 21.1 总览

本节先给出全貌：GPU 的每个部件对应于抽象芯片（定义 6.1）的哪一部分，以下各节再逐个展开。

| 抽象芯片 | GPU |
| --- | --- |
| 核心 | **SM**（streaming multiprocessor），每颗芯片一百多个 |
| 控制单元 | 每个 SM 4 个 **warp 调度器**，动态地从驻留的 warp 中选择可以执行的 |
| 向量单元 | 每个调度器下的若干组运算单元，按 **SIMT** 方式执行（21.2 节） |
| 矩阵单元 | **Tensor Core**，每个 SM 4 个 |
| 片上存储 | **寄存器堆**（每 SM 256 KB）、**共享内存**与 L1 缓存（每 SM 两三百 KB）、全芯片共享的 **L2 缓存**（几十到一百多 MB） |
| 片外存储 | **HBM**（数据中心 GPU）或 GDDR（消费级 GPU） |
| 搬运机构 | 线程的读写指令、异步拷贝（cp.async）、张量搬运引擎（**TMA**） |
| 互联 | **NVLink** 与 **NVSwitch**；跨机器用网卡 |

与 TPU 相比，GPU 的核心多而小，有缓存，控制是动态的。

## 21.2 SIMT：线程、warp 与调度

本节说明 GPU 最根本的执行方式：程序按线程写成，硬件按 warp 以 SIMD 的方式执行（定义 21.1）；以及线程块怎样被调度到 SM 上。

> **定义 21.1（SIMT）** 程序以**线程**为单位编写，每个线程有自己的寄存器和程序计数器的逻辑视图。硬件把 32 个线程编为一个 **warp**，一个 warp 的 32 个线程同时执行同一条指令，各自使用自己的寄存器：这就是宽度 $w = 32$ 的 SIMD（定义 4.7），每个线程是一个通道。

所以 SIMD 的三条代价（4.3 节）在 GPU 上都存在：

1. **分支分歧**：同一个 warp 的线程走不同的分支时，硬件用掩码依次执行各个分支（习题 4.5）。
2. **数据的摆放**：一个 warp 的 32 个线程同时访存，地址的分布决定了访存的效率（21.3 节）。
3. **线程间的数据交换**：同一个 warp 内可以用专门的洗牌指令交换寄存器中的值；跨 warp 要经过共享内存。

**线程块与调度。** 线程编成**线程块**（block，也称 CTA），一个块至多 1024 个线程。一个块被整体分配给一个 SM，它的全部 warp 驻留在这个 SM 上直到结束，共享这个 SM 的共享内存，可以在块内同步。一个 SM 同时驻留多个块，最多数十个 warp。SM 分为 4 个子分区，每个子分区有一个 warp 调度器、一部分寄存器堆和运算单元；每个周期，每个调度器从它的 warp 中选出一个可以执行的（操作数已就绪），发射一条指令。

这就是命题 4.9 的多线程：一个 warp 在等存储时，调度器换另一个 warp。代价是所有驻留 warp 的寄存器都要常驻在寄存器堆中，所以 GPU 的寄存器堆（每 SM 256 KB）比 L1 缓存还大。

## 21.3 寄存器、共享内存与缓存

接下来看线程能访问的各级存储：寄存器、共享内存、缓存与全局内存，以及各自的访问规则。

**寄存器。** 每个 SM 有 65536 个 32 位寄存器，每个线程至多使用 255 个。一个 kernel 每个线程用的寄存器越多，一个 SM 能同时驻留的线程就越少（21.4 节）。寄存器放不下的变量会**溢出**到片外存储（经由缓存），代价很大。

**共享内存**是每个 SM 上由程序显式管理的便签存储（定义 3.6），与 L1 缓存共用一块 SRAM，比例可以配置。它分成 32 个 4 字节宽的存储体（定义 3.3）：一个 warp 的 32 个访问若落在不同的存储体上，一个周期完成；否则按冲突度串行（命题 3.4）。第 8 章的 XOR 交错（命题 8.7）就是为它准备的。

**缓存。** 每个 SM 有 L1 缓存；全芯片共享一个大的 L2 缓存。L2 的容量足以放下一些中等大小的张量，使得重复读取同一份数据的块（例如矩阵乘法中被多个块读取的权重块）大多在 L2 中命中，而不必每次都到 HBM。

**全局内存的访问粒度**是 32 字节的段。一个 warp 的一次访存，代价取决于它触及多少个段（定义 8.11）：32 个线程读连续的 32 个 f32（128 字节）只需 4 个段；若每个线程读的地址相隔 128 字节，就要 32 个段，效率只有 $1/8$（命题 8.12）。这条规则在 GPU 上称为**访存合并**。

## 21.4 延迟隐藏与占用率

21.2 节说，GPU 靠驻留大量 warp 来隐藏延迟。能驻留多少，受资源限制；需要驻留多少，由 Little 定律决定。本节分别算出这两个数（命题 21.3、21.4），并说明现代 kernel 为什么转向另一种策略。

> **定义 21.2（占用率）** 一个 SM 上驻留的 warp 数与它允许的最大 warp 数之比，称为**占用率**。它受以下资源的限制：每线程的寄存器数、每块的共享内存、每块的线程数、每 SM 的最大块数。

> **命题 21.3（占用率的上限）** 设 kernel 每线程用 $r$ 个寄存器、每块 $T$ 个线程与 $S$ 字节共享内存，SM 有 $R$ 个寄存器、$S_{\text{SM}}$ 字节共享内存，至多 $W$ 个 warp。则每个 SM 驻留的块数至多为
>
> $$
> \min\!\left(\left\lfloor \frac{R}{rT} \right\rfloor,\ \left\lfloor \frac{S_{\text{SM}}}{S} \right\rfloor,\ \left\lfloor \frac{32W}{T} \right\rfloor,\ (\text{每 SM 的最大块数})\right).
> $$

（实际的寄存器与共享内存按一定粒度分配，结果可能稍小。）

占用率要多高？由 Little 定律回答。

> **命题 21.4（跑满带宽所需的在途数据）** 设芯片有 $n_{\text{SM}}$ 个 SM，HBM 带宽 $B$、延迟 $L$。要跑满带宽，每个 SM 平均要有 $BL / n_{\text{SM}}$ 字节的读请求在途。

*证明* 推论 4.5，平均分到每个 SM。∎

以带宽 3.35 TB/s、延迟约 700 ns、132 个 SM 的芯片为例，每个 SM 约需 18 KB 在途。若每个线程只有一个 16 字节的读请求在途，一个 warp 是 512 字节，就需要约 35 个 warp：很高的占用率。于是有两种策略：

- **靠占用率**：让很多 warp 驻留，每个 warp 少量在途；
- **靠每个 warp 的在途量**：让少数 warp 每个都有很多请求在途，例如一个线程连续发出多个独立的读、使用异步拷贝、或者让搬运引擎一次搬运一大块（21.6 节）。

早期的 GPU kernel 多用第一种；现代的矩阵乘法与注意力 kernel 每个 SM 只驻留少数几个 warp 组，靠深的异步流水线（第 9 章）维持在途的数据量，用第二种。

## 21.5 Tensor Core 的演变

Tensor Core 是 GPU 的矩阵单元（第 5 章）。它对程序的接口（定义 5.8）在几代之间变化很大，而变化的方向是一致的：**矩阵单元越来越大，越来越与线程解耦，越来越直接从片上存储读取操作数**。

- **Ampere**（sm_80，消费级为 sm_86）：warp 级的同步 MMA 指令。一个 warp 的 32 个线程共同提供 $A$、$B$、$C$ 的片段（每个线程寄存器中存放片段的一部分，按固定的布局），执行例如 $m16n8k16$（bf16）的乘加。操作数要先从共享内存读入寄存器（有专门的按矩阵布局读取的指令）。支持 tf32、bf16、fp16、int8 和 2:4 稀疏。
- **Hopper**（sm_90）：**warpgroup 级的异步 MMA**（wgmma）。4 个 warp（128 个线程）组成一个 warpgroup，共同发起一次 $m64nNk16$（$N$ 至多 256）的乘法；$B$（以及可选的 $A$）直接从共享内存读取，要求按规定的交错布局存放；累加结果在这 128 个线程的寄存器中。指令是异步的：发起后可以做别的事，再等待完成。支持 fp8。
- **Blackwell**（sm_100）：**单线程发起的异步 MMA**（tcgen05）。一个线程发起整个块的乘法；操作数来自共享内存（$A$ 也可以来自张量存储）；累加结果放在新的**张量存储**（TMEM）中：每个 SM 256 KB，组织为 128 行 × 512 列的 32 位单元。单个线程块的 MMA 形状可达 $128 \times 256$，一对线程块（CTA 对）合作可达 $256 \times 256$，各自提供一半的数据、保存一半的累加结果。完成时通知一个 mbarrier。硬件支持 MX 格式与 NVFP4 的块缩放乘法（2.8 节）。

> **现状（2026-10）**：Rubin 把 Tensor Core 每周期沿 $K$ 方向处理的数据量加倍，主打格式是 NVFP4（每 GPU 约 50 PFLOP/s）。据公开资料，消费级 Blackwell（sm_120）没有 tcgen05 与张量存储，矩阵运算仍使用 warp 级的 MMA 指令（支持 fp4）。

> **注 21.5（对照）** 这个演变方向使 GPU 的矩阵单元越来越接近 TPU 的 MXU：都是一个由少数指令驱动、从片上存储读操作数、异步完成的大矩阵单元。不读 TPU 路线的读者可以跳过这条注。

## 21.6 异步搬运：cp.async 与 TMA

要以少数 warp 维持大量在途的数据（21.4 节），搬运必须是异步的（定义 4.10）。本节讲两种异步搬运机制，以及与之配合的同步对象。

- **cp.async**（Ampere 起）：每个线程发起从全局内存到共享内存的异步拷贝（每次 4、8 或 16 字节），不经过寄存器；用"提交一组、等待若干组完成"的方式同步。
- **TMA**（tensor memory accelerator，Hopper 起）：一个专门的搬运引擎。程序事先建立一个**张量描述符**（基地址、各维长度与步长、要搬运的块形状、共享内存中的交错方式），之后**一个线程**发出一条指令，就能在全局内存与共享内存之间搬运整个多维块，还可以把同一块同时送给簇中的多个线程块（多播）。地址的计算与越界的处理都由引擎完成，不占用线程的寄存器与指令。

**mbarrier**是放在共享内存中的同步对象，是定义 9.5 的一个变体：它记录预期的到达次数与预期的字节数，以及一个"相位"位。TMA 完成搬运时按字节计数；Tensor Core 完成乘法时也可以通知它。等待者等的是"本相位的计数已满"，之后相位翻转，这个 mbarrier 可以再用于下一轮（这正是多缓冲中每个缓冲各用一个同步对象、反复复用的做法）。

## 21.7 线程块簇与分布式共享内存

Hopper 引入**线程块簇**（cluster）：若干个线程块（可移植的上限是 8 个）保证被同时调度到相邻的一组 SM 上。簇内的线程块可以直接读写彼此的共享内存（**分布式共享内存**），可以在簇的范围内同步，TMA 可以把一块数据多播给簇内的多个线程块。用途是让相邻的线程块共享操作数的块，减少从 L2 和 HBM 重复读取，以及组成 Blackwell 的 CTA 对。

## 21.8 互联

最后走出芯片。GPU 之间的连接分三层：

- **NVLink**：GPU 之间的点对点高速链路。
- **NVSwitch**：交换芯片，把一组 GPU 连成全带宽的交换网络（定义 7.2 中交换机的情形）。常见的一台服务器有 8 颗 GPU；NVL72 一类的机柜把 72 颗 GPU 放进同一个 NVLink 交换域。
- 跨越交换域，经由每颗 GPU 配备的网卡（InfiniBand 或以太网）通信，带宽比 NVLink 低一个数量级。

所以 GPU 系统的拓扑是分层的交换网络：域内是全带宽的交换机，二分带宽高（7.1 节的表），全交换代价低；域间带宽低得多。第 12 章的原则据此具体化：张量并行与专家并行放在 NVLink 域内，数据并行与 FSDP 可以跨域。

## 接口小结

1. GPU = 许多 SM；每个 SM 有 4 个动态调度的 warp 调度器、运算单元、4 个 Tensor Core、256 KB 寄存器堆、两三百 KB 的共享内存与 L1；全芯片共享 L2 与 HBM。（21.1 节）
2. SIMT：32 个线程组成 warp，以 SIMD 方式执行；分支分歧用掩码；线程块整体驻留在一个 SM 上，块内共享共享内存、可以同步。（定义 21.1）
3. 共享内存有 32 个 4 字节的存储体；全局内存以 32 字节为段，一个 warp 的访存代价是它触及的段数。（21.3 节）
4. 占用率受寄存器、共享内存、线程数、块数限制（命题 21.3）；每个 SM 要有 $BL/n_{\text{SM}}$ 字节在途，可以靠占用率，也可以靠每个 warp 的异步在途量。（命题 21.4）
5. Tensor Core：Ampere 是 warp 级同步 MMA（操作数在寄存器）；Hopper 是 warpgroup 级异步 MMA（操作数可直接来自共享内存，累加在寄存器）；Blackwell 是单线程发起的异步 MMA（累加在 256 KB 的 TMEM，可用 CTA 对），支持块缩放格式。（21.5 节）
6. 异步搬运：cp.async（逐线程）、TMA（一个线程搬运整个多维块，按描述符，可多播）；mbarrier 按次数与字节计数，有相位，可反复使用。（21.6 节）
7. 簇让相邻的线程块共享共享内存并一同调度；NVLink/NVSwitch 组成全带宽交换域，域间走网卡。（21.7、21.8 节）
8. 各代参数见 21.9 节；GPU 的时间取决于运行时，但屋顶线估算同样有效。

## 习题

**习题 21.1** ★ 一个 kernel 每线程用 128 个寄存器，每块 256 个线程、48 KB 共享内存。SM 有 65536 个寄存器、228 KB 共享内存、至多 64 个 warp、至多 32 个块。按命题 21.3，每个 SM 能驻留几个块？占用率是多少？若把寄存器降到 64 个呢？

<details><summary>提示</summary>

逐项计算命题 21.3 中的四个量。

</details>
<details><summary>答案</summary>

寄存器：$65536 / (128 \times 256) = 2$；共享内存：$\lfloor 228/48 \rfloor = 4$；warp：$64 \times 32 / 256 = 8$；块数 32。至多 2 个块，16 个 warp，占用率 25%。寄存器降到 64 个时，寄存器的限制变为 4，与共享内存的限制相同，4 个块、32 个 warp，占用率 50%。

</details>

**习题 21.2** ★ 用命题 21.4，对 B200（8 TB/s、148 个 SM，设延迟 800 ns）求每个 SM 需要多少字节在途。若一个 SM 只驻留 3 个 warpgroup（12 个 warp），每个 warp 平均要有多少字节在途？用逐线程的 16 字节读能做到吗？

<details><summary>提示</summary>

每个 warp 一次 16 字节的读，在途 512 字节。

</details>
<details><summary>答案</summary>

$8 \times 10^{12} \times 8 \times 10^{-7} / 148 \approx 43$ KB。12 个 warp 时每个 warp 约 3.6 KB，相当于每个线程同时有约 7 个 16 字节的读在途，需要很深的软件流水线和大量寄存器。用 TMA 一次搬运一个几十 KB 的块，单条指令就能提供这样的在途量。这就是现代 kernel 依赖 TMA 的原因。

</details>

**习题 21.3** ★ 一个 warp 的 32 个线程各读一个 bf16，第 $i$ 个线程读地址 $a_0 + 2i$（字节），$a_0$ 是 32 的倍数。触及几个段？若每个线程改为读 8 个连续的 bf16（一次 16 字节的读）呢？若第 $i$ 个线程读第 $i$ 行的第一个元素，行长为 4096 个 bf16 呢？

<details><summary>提示</summary>

定义 8.11，段长 32 字节。

</details>
<details><summary>答案</summary>

64 字节连续，2 个段，效率 100%。每线程 16 字节时 512 字节连续，16 个段，效率 100%，而且一次读到的数据是前者的 8 倍。读每行的第一个元素时相邻地址相隔 8192 字节，32 个段，每段只用 2 字节，效率 $1/16$。

</details>

**习题 21.4** ★ 在 Blackwell 上，一个线程块计算 $128 \times 256$ 的输出块，累加结果为 f32，放在 TMEM 中。它占 TMEM 的多少？能否在 TMEM 中放两份累加器？这有什么用？

<details><summary>提示</summary>

TMEM 是 128 行 × 512 列的 32 位单元。

</details>
<details><summary>答案</summary>

$128 \times 256$ 个 f32 占 256 列，恰为 TMEM 的一半，可以放两份。用途：当一份累加器正在被读出、做结尾融合并写回（第 23 章）时，Tensor Core 可以在另一份上开始下一个输出块的乘法，结尾与主循环重叠，即累加器的双缓冲。

</details>

**习题 21.5** ★ 共享内存中按行存放一个 $64 \times 64$ 的 bf16 块（每行 128 字节）。一个 warp 要读取一列的 32 个元素（第 $i$ 个线程读第 $i$ 行第 $j$ 列）。冲突度是多少？用 16 字节为单位的 XOR 交错（习题 8.4）后，读"一列 16 字节的块"（每个线程读第 $i$ 行的第 $c$ 个 16 字节块）的冲突度是多少？

<details><summary>提示</summary>

存储体宽 4 字节，32 个存储体覆盖 128 字节，恰为一行。

</details>
<details><summary>答案</summary>

每行 128 字节恰好覆盖 32 个存储体一次，第 $i$ 行第 $j$ 列总在同一个存储体，32 个访问冲突度为 32。按 16 字节交错后，第 $i$ 行的第 $c$ 个块存放在位置 $c \oplus (i \bmod 8)$：每 8 行在 8 个不同的 16 字节位置上，16 字节的访问以 4 个存储体为一组，8 个位置覆盖全部 32 个存储体。32 个线程的 16 字节访问共 512 字节，至少要 4 个周期（硬件每周期服务 128 字节），交错后恰好 4 个周期，没有额外的冲突。

</details>

**习题 21.6** ☆ 72 颗 GPU 在一个 NVLink 交换域中，每颗 GPU 的单向 NVLink 带宽为 900 GB/s。用命题 7.3 估计每颗 GPU 向其余每颗各发 1 MB 的全交换至少需要多少时间。若同样的 72 颗 GPU 只能经由每颗 50 GB/s 的网卡通信呢？

<details><summary>提示</summary>

无阻塞交换机的二分带宽为 $\frac{p}{2}\beta$。

</details>
<details><summary>答案</summary>

$(72/2)^2 \times 10^6 / (36 \times 9 \times 10^{11}) = 1.296 \times 10^9 / 3.24 \times 10^{13} \approx 40$ µs。经网卡时（假设网络本身无阻塞）为 $1.296 \times 10^9 / (36 \times 5 \times 10^{10}) \approx 0.72$ ms，慢 18 倍。这就是专家并行要尽量限制在 NVLink 域内的原因。

</details>
