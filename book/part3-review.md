# 第三部分　回顾与自测

第三部分把第二部分的计算规格写成 JAX 程序。全部内容可以归结为一件事：JAX 先把 Python 函数追踪成一个有类型的小程序（jaxpr），编译、求导、向量化、分片都是对这个小程序的加工。分布式程序里，这个"类型"还包括分片：全局数组的形状、每台设备上的局部形状和复制在哪些轴上，要分开核对。这一部分是 TPU 路线的必读；GPU 路线的读者只在第 25 章讲 Pallas GPU 的一节用到它。

## 这一部分的骨架

1. 追踪只看抽象值（形状、数据类型、分片），所以不能依据数组的值做 Python 控制流，形状必须静态，Python 循环会被展开；`jit` 按抽象类型和静态参数缓存编译结果。（定义 13.3、13.3 节）
2. 自动微分：JVP 是雅可比矩阵乘向量，VJP 是向量乘雅可比矩阵；VJP 由 JVP 加线性转置得到，要保存残差；$y = xW$ 的 VJP 是 $\bar{y}W^{\mathsf T}$ 与 $x^{\mathsf T}\bar{y}$。（定义 13.6、命题 13.7）
3. `vmap` 按原语的批处理规则加批量维；控制流用 `cond`、`scan` 等原语；随机数用显式密钥。（定义 13.9、13.6、13.7 节）
4. 分片是类型的一部分：Explicit 模式在追踪时按命题 12.4 的规则推出输出的分片，有歧义时要求程序员写明；`shard_map` 以每台设备的视角写程序，通信由集合原语显式完成。（定义 14.3、14.3 节）

**最常用的节。** 13.1–13.4 节，14.1–14.3 节。

**这时可以读的附录。** 附录 B 的 B.1 节（JAX 的概念与 API 对照）；附录 C 的 C.4 节"多设备"一组，以及 C.5 节第 4 条（在编译结果中数集合通信）。

## 自测题

**1.** 一个函数里写了 `if x.sum() > 0:`，放进 `jax.jit` 会怎样？`if x.shape[0] == 4:` 呢？为什么？

<details><summary>答案与出处</summary>

前者报错：追踪时 `x` 是只知道形状和类型的占位对象，回答不了"和是否大于 0"；要写成 `jnp.where` 或 `lax.cond`。后者没问题：形状是追踪时已知的静态信息，分支在追踪时就选好了（13.2 节、例 13.4）。

</details>

**2.** 一个训练循环每一步的输入长度都不同，为什么很慢？怎样修？

<details><summary>答案与出处</summary>

`jit` 以（抽象类型，静态参数）为键缓存编译结果；形状每步都变，每步都要重新追踪和编译，编译要几秒到几分钟（13.3 节）。把长度补齐到少数几个固定的档位，用掩码忽略补出来的部分。

</details>

**3.** 训练为什么用 VJP（反向模式）而不是 JVP？代价是什么？

<details><summary>答案与出处</summary>

损失是一个数，参数有几百万到几十亿个。一次 VJP 给出雅可比矩阵的一行，也就是全部梯度；用 JVP 要做与参数个数一样多次（定义 13.6、例 13.8、命题 M5.8）。代价是要保存前向的中间结果（残差），这就是激活显存；`jax.checkpoint` 用重算换显存（13.4 节）。

</details>

**4.** 写出 $y = xW$ 的 VJP，并说明"反向是前向的两倍"从哪里来。

<details><summary>答案与出处</summary>

$\bar{x} = \bar{y} W^{\mathsf T}$，$\bar{W} = x^{\mathsf T} \bar{y}$（命题 13.7）。前向一个矩阵乘法，反向两个同样大小的矩阵乘法，所以训练每词元约 $6\Phi$ FLOP（命题 11.16）。

</details>

**5.** 用同一个随机密钥生成两层的 dropout 掩码，会出什么问题？

<details><summary>答案与出处</summary>

生成随机数是纯函数，同一个密钥、同样的形状，两份结果完全相同，两层的掩码一模一样，产生了不该有的相关性。应从主密钥 `split` 出两份子密钥，各用一次（例 13.12）。要让结果与设备数无关，还要按全局下标计数（13.7 节）。

</details>

**6.** Explicit 模式下，两个收缩维都沿轴 `x` 分片的矩阵乘法为什么报错？应当怎样写？

<details><summary>答案与出处</summary>

每台设备算出的是部分和，输出既可以 all-reduce 成复制的结果，也可以 reduce-scatter 成分片的结果，分片有歧义（命题 12.4 情形 2）。要用 `out_sharding` 写明要哪一种（14.2 节、例 14.4）。两种选择的数值结果相同，之后的局部尺寸和通信不同。

</details>

**7.** 在 `shard_map` 里对一个本来就复制的标量做 `psum`，结果是什么？

<details><summary>答案与出处</summary>

它的 $\lvert x \rvert$ 倍：每台设备都贡献了同一个值（14.3 节、例 14.6）。反过来，`out_specs` 中省略一个轴只是声明"各设备的输出本来就相同"，不会替你做一次 all-reduce。

</details>

**8.** 怎样确认一个 JAX 程序的通信是你想要的？

<details><summary>答案与出处</summary>

看编译后的 HLO：`jax.jit(f).lower(x).compile().as_text()`，数里面的集合通信的种类和次数，与规格中的预期对照，例如梯度规约应当是 reduce-scatter 而不是 all-reduce 加切片（13.3 节，附录 C 的 C.5 节）。

</details>
