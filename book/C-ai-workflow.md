# 附录 C　与 AI 协作：规格与审查

本书默认读者让 AI 写代码，自己负责三件事：写出精确的规格，估出性能的上限，审查 AI 交回的代码。本附录把正文中分散的要点整理成可以直接使用的模板与清单。

## C.1 分工

| 读者 | AI |
| --- | --- |
| 用数学写出要计算什么（形状、类型、语义） | 按规格写代码 |
| 决定数据流：分块、布局、流水线、分片、同步关系 | 处理 API 的细节、样板代码、构建与运行 |
| 用屋顶线估出时间下界和应有的瓶颈 | 写测试、运行解释器、导出编译结果 |
| 审查正确性与性能，决定是否接受 | 按审查意见修改 |

AI 擅长把清楚的规格变成代码，不擅长在规格不清时做出正确的取舍；而第 9、19、23 章的例子说明，同步错误往往能通过普通的测试。所以规格要写得具体，审查要以推理为主、测试为辅。

## C.2 规格模板

### 单个 kernel

```text
1. 计算：用公式写出输出与输入的关系（含掩码、缩放、边界情形）。
2. 形状与类型：每个输入、输出的形状与数据类型；累加器的类型（f32）；哪些维可能不是块大小的倍数。
3. 布局：输入输出在存储中的布局；硬件要求的对齐（TPU 的 (8, 128)、GPU 的 16 字节与交错）。
4. 分块：块的形状、grid（或线程块）的形状与遍历次序；哪些维按顺序执行（"arbitrary"）、哪些可以并行。
5. 数据移动：每个操作数怎样进入片上存储；流水线的级数；预计的片上存储用量。
6. 同步：每个缓冲由谁写、谁读；用哪个信号量或 mbarrier 保护；何时可以覆盖。
7. 数值：累加精度；缩放因子的位置；全屏蔽行、越界元素的处理；是否要求确定性。
8. 性能目标：按屋顶线算出的时间下界、预期的瓶颈（哪一级存储或哪个单元），可以接受的比例。
9. 验证：参考实现、误差的容许范围及理由、必须覆盖的边界情形、对抗性的检查方式（见 C.5）。
```

### 分布式程序

```text
1. 网格：各网格轴的大小，以及它们对应的物理拓扑（哪一轴在最快的链路上）。
2. 分片：每个参数、激活、梯度、优化器状态的 PartitionSpec。
3. 预期的通信：按命题 12.4 推出每个矩阵乘法需要的集合操作；其余位置不应出现通信。
4. 重叠：哪些通信要与计算重叠，怎样切分（命题 7.18、27.1）。
5. 显存：每台设备上参数、梯度、优化器状态、激活的估计，是否需要重计算或卸载。
6. 性能目标：计算时间、每个轴的通信时间（只计带宽项与固定开销），能否掩盖。
```

## C.3 估算清单

1. 数出运算量 $F$（矩阵乘法 $2MNK$，注意力 $4T^2d$ 等）与每一级存储的数据量 $Q_\ell$。
2. 算出强度 $I_\ell = F / Q_\ell$，与各级的拐点 $P / B_\ell$ 比较（定理 6.5、命题 6.18）。
3. 时间下界 $\max(F/P, Q_\ell / B_\ell)$；很小的计算还要加上固定开销（6.2 节）。
4. 小批量的矩阵乘法：强度约 $2N/s$，权重的字节数就是时间（命题 6.20）。
5. 多设备：每个集合操作的带宽项与固定开销（第 7 章），与计算比较能否掩盖（命题 12.6、12.8）。
6. 显存：每台设备的总量是否放得下（11.3 节）。

## C.4 审查清单

**数值**（第 2、10 章）

- 累加器是 f32；bf16 矩阵乘法显式要求 f32 结果；只在最后舍入一次。
- softmax 减去最大值；越界与被屏蔽的位置填归约的单位元；全屏蔽的行不产生 NaN。
- 方差用 Chan/Welford 的合并，而不是"平方和减平方"。
- 块缩放在每个 $K$ 块累加前应用；按输出通道的缩放可以留到结尾。
- 需要确定性时，没有浮点的原子累加，归约树与配置无关。

**同步**（第 9 章）

- 每个缓冲：读之前等待它的写入；覆盖之前等待它的所有读者，包括向外的 DMA 与异步的 MMA。
- 并发的异步操作各用一个信号量；等待的计数与信号的计数单位一致。
- 没有等待的环；先发信号、后等待。
- 结束时信号量归零；序幕与尾声没有越界，也没有漏掉最后的等待。

**Pallas TPU**（第 16、17 章）

- 块的最后两维满足 $(8, 128)$ 的倍数（窄类型更大）；VMEM 预算放得下。
- 累加的维是 `"arbitrary"`，累加器在第一步清零、最后一步写出。
- 每个输入的读取次数与理想值一致（命题 16.3）。
- 解释器中正确不代表能在 TPU 上编译，更不代表性能好。

**TPU 指令**（第 20 章）

- 内层循环的指令包数与估计一致；瓶颈的槽是预期的单元；MXU 的乘法与取回交错；稳态中没有等待 DMA。

**GPU**（第 22、23、25 章）

- `__syncthreads()` 不在分歧的分支中；全局访存合并、向量化；共享内存无冲突。
- 多级流水线中，MMA **完成**之后才释放它读过的一级。
- 寄存器没有溢出；在途的字节数足够；块数与 SM 数的关系合理。
- 结尾融合了能融合的运算，并与下一块的主循环重叠。

**多设备**（第 14、19、27 章）

- 所有参与者以相同的次序调用相同的集合操作。
- 编译后的程序中只出现预期的集合通信（例如梯度规约是 reduce-scatter 而不是 all-reduce 加切片）。
- 跨设备的写入之前有屏障；跨设备的标志用系统作用域的释放与获取；推送式通信有信用机制。

## C.5 让 AI 自证

审查以推理为主，但可以要求 AI 提供以下证据，使推理更快：

1. **参考实现与误差界**：用最直接的写法（f64 或 f32）实现同一个计算，比较结果；容许的误差要有理由（第 2 章的误差界）。
2. **覆盖边界情形的随机测试**：形状不是块大小的倍数、长度为 1、空的组、全被屏蔽的行、极大与极小的数值。
3. **对抗性的执行方式**：Pallas 解释器的竞争检测（`detect_races=True`）与推迟执行 DMA 的模式（`dma_execution_mode="on_wait"`，例 19.5 的错误正是这样发现的）；GPU 上的 `compute-sanitizer` 竞争检查。
4. **编译结果中的计数**：在 HLO 中数集合通信的种类与次数、在指令包或 SASS 中数某类指令，与规格中的预期对照。
5. **与屋顶线的对照**：在有硬件时，实测时间与 C.3 的下界之比；比值偏离时，要求 AI 说明差距落在哪一级。

## C.6 一个例子

下面是交给 AI 的一份规格（TPU，Pallas），说明模板中各项应当写到什么程度：

```text
计算：Y = RMSNorm(X) @ W，X: bf16[N, D]，W: bf16[D, F]，g: bf16[D]，
      RMSNorm(x) = x / sqrt(mean(x^2) + 1e-6) * g。N = 8192，D = 4096，F = 14336。
做法：按命题 17.6，W' = diag(g) W 离线算好；第一个 kernel 求每行 r_i（f32，按行块，
      每行一个数）；第二个 kernel 是分块矩阵乘法 X @ W'，在结尾对每行乘 r_i。
分块：bM = bN = 512，bK = 1024；grid = (N/bM, F/bN, D/bK)，最后一维 "arbitrary"。
      r 的 BlockSpec 为 (bM, 1)，只依赖 i。
数值：累加器 f32 scratch；r 在 f32 中计算；输出 bf16。
目标：v5e 上矩阵乘法 2NDF = 9.6e11 FLOP，下界约 4.9 ms（计算受限，命题 17.1）；
      第一个 kernel 读 X 一遍（64 MiB），约 0.08 ms。
验证：与 jnp 的直接实现比较，相对误差 < 2e-2；N、F 取非 512 倍数时补齐的测试；
      解释器中运行，开启竞争检测。
```

这份规格中的离线合并假定 g 与 W 在调用之间保持固定，适用于推理。训练时它们更新后必须重新构造 $W'=GW$，并让求导继续依赖原参数；低精度合并也可能改变舍入路径。`r` 的逻辑形状是每行一个数，真实 TPU 布局是否需要通道复制应单独核对，不能把其逻辑字节数直接当作物理预算。

## C.7 GPU 的对应规格

同样的写法适用于 GPU。下面给出 $Y=\operatorname{ReLU}(AB+b)$ 的规格，重点是完整和、完成身份和资源预算，不要求 AI 手写所有汇编。

```text
目标：Hopper 的适用目标，CUDA/CUTLASS 或能表达同一数据流的 tile 接口。
数学：A[1024,512]，B[512,2048]，b[2048]，输入输出 bf16；f32 累加。
      输出为 ReLU(AB+b)，偏置只加一次，非线性只在全部 K 部分积合并后执行。
块：输出 128×128，K 步 64；输出网格 8×16；每个输出块有唯一逻辑所有者。
局部状态：4 级输入槽，每级 A、B 各 16 KiB，共 128 KiB 共享输入缓冲；
          再计屏障、输出暂存和对齐，核对每块上限，不能只用每 SM 总容量。
执行：TMA 生产者按消费者所需交错写入；矩阵消费者持有自己的完整 K 累加。
同步：每槽 full 声明 A+B 共 32768 字节与匹配的到达次数；
      empty 仅在所有相关 MMA 读完后发布；第一圈和最后一组分别处理。
结尾：等待累加器最后的异步写入后读取，执行偏置、ReLU、舍入、写回；
      输出暂存只有在写回引擎读完之后才可复用。
代价：无 L2 复用的输入块流量 32 MiB，输出 4 MiB；另计偏置与元数据。
      不假定常见 tile 能跑满 HBM 或 Tensor Core，逐级比较下界。
证据：输出覆盖、K 累加不变量、每槽生命周期、精度路径与每级资源预算。
      若没有目标硬件或工具链，明确标注尚未编译和测量。
```

这个规模共 $2\cdot1024\cdot2048\cdot512=2^{31}$ FLOP。按附录 A 的 H100 稠密峰值估，纯矩阵计算约 2.17 µs；无块间复用的 36 MiB 流量按 3.35 TB/s 约 11.3 µs。前者是计算下界，后者是特定流量假设下的带宽下界；真实 L2 复用、尾波和结尾会改变它们的比较。看到 2.17 µs 便要求 AI 达到它，等于忽略其余资源。

## C.8 一页纸的证明怎样组织

接受代码之前，先让 AI 给出三段连贯的论证。第一段证明数学语义：哪些下标被哪个任务覆盖，K 部分和怎样积累，掩码与缩放什么时候应用。第二段证明存储安全：每份缓冲有哪些写者和读者，完成对象对应哪轮哪份数据，复用之前是否全读完。第三段给出代价：每一级多少字节、每类单元多少操作、同时存活的容量，以及假设哪些资源能重叠。

测试结果只为这些论证提供补充证据。解释器不能证明真实布局合法，编译通过不能证明性能达标，一个输入算对不能证明异步协议正确。把缺失的证据定位到某一段，修改规格就有明确方向。
