# 第五部分　回顾与自测

第五部分是 GPU 路线。GPU 是一台"动态"的机器：每个 SM 驻留大量线程，硬件每个周期挑出操作数已经就绪的 warp 发射，用很多个同时在途的请求藏住访存的延迟。这一部分从 SM 和 SIMT 模型出发，经过线程、共享内存与归约，走到异步搬运、mbarrier、warp 专门化和新一代的矩阵指令，再写出矩阵乘法、注意力和多 GPU 通信。本部分的论证不依赖第三、四部分。

## 这一部分的骨架

1. SIMT：线程以 32 个为一组（warp）同步发射，分支要两边都走；占用率是驻留的 warp 数，真正决定带宽的是在途的数据量。（定义 22.2、命题 22.6、22.8）
2. 全局访存看合并（触及多少个段），共享内存看存储体冲突；两者管的是不同的路，不能互相替代。（例 22.4、命题 3.11）
3. 多级流水线的满/空槽协议：数据到齐才能读，MMA 完成之后才能释放它读过的一级；mbarrier 用相位区分两轮。（定义 24.1、命题 24.5）
4. GEMM 要逐级去掉瓶颈，每一级都用逐级的屋顶线验证；缩放因子随 $k$ 变化时，要在每个 $K$ 块累加之前乘上。（26.1 节、命题 26.2）
5. FlashAttention 用在线状态一块块处理键值，$T \times T$ 的矩阵不进 HBM；在新一代 GPU 上指数单元可能成为瓶颈。（第 27 章、命题 27.4）
6. 所有参与者必须以相同的次序调用相同的集合操作；分块重叠的块数要在首尾暴露与固定开销之间权衡。（28.5 节、命题 28.4）

**最常用的节。** 22.1–22.6 节；23.1、23.3–23.6 节；24.1–24.6、24.8 节；25.1、25.2、25.6、25.7 节；26.1–26.3 节；27.1–27.5、27.7 节；28.1、28.3、28.5 节。

**这时可以读的附录。** 附录 C 的 C.2 节"单个 kernel"模板、C.4 节的"GPU"与"多设备"两组、C.7 节（一份 GPU 规格的例子）和 C.9 节（KernelBench 等公开研究）；附录 A 的 A.3 节与附录 B 的 B.3、B.4、B.6 节是查参数和 API 用的。

## 自测题

**1.** warp 分歧、访存合并、存储体冲突分别是什么？合并和无冲突能互相替代吗？

<details><summary>答案与出处</summary>

分歧：同一 warp 的线程走不同分支，两条路依次执行（例 22.3）。合并：一个 warp 的全局访存触及的 32 字节段越少越好（22.3 节、定义 8.17）。冲突：一个 warp 访问共享内存时多个地址落在同一存储体（命题 3.11）。前者管"HBM → 共享内存"，后者管"共享内存 → 寄存器"，互不替代（例 22.4）。

</details>

**2.** 要跑满 3.35 TB/s 的 HBM、延迟约 700 ns，一块有 132 个 SM 的 GPU，每个 SM 要有多少数据在途？占用率越高越好吗？

<details><summary>答案与出处</summary>

由 Little 定律，全芯片约 2.3 MB 在途，每个 SM 约 18 KB（命题 22.8）。占用率只说明驻留了多少 warp（命题 22.6）；在途的数据量也可以来自每个线程的多个独立操作或 TMA 的大块搬运。高性能的 GEMM 和注意力 kernel 每个 SM 只驻留少数几组 warp，用大寄存器分块换复用（23.6 节）。

</details>

**3.** 一个 warp 怎样在 5 步内求出 32 个数的和，并让每个线程都拿到结果？

<details><summary>答案与出处</summary>

XOR 洗牌：第 $k$ 步每个线程与编号异或 $2^k$ 的线程交换并相加，5 步之后每个线程都持有总和（命题 23.6）。这是命题 1.42 的二叉树，结构上和递归倍增的 all-reduce 一样（7.6 节）。

</details>

**4.** Ampere、Hopper、Blackwell 的 Tensor Core 接口有什么区别？

<details><summary>答案与出处</summary>

谁发起：32 个线程、128 个线程（warpgroup）、1 个线程；操作数：寄存器、共享内存；累加：寄存器、寄存器、TMEM（22.5 节）。方向是矩阵单元越来越大、越来越不依赖线程、越来越直接从片上存储读数。

</details>

**5.** 解释 Hopper 上一个 GEMM kernel 的结构：TMA、mbarrier、warp 专门化各干什么？最常见的同步错误是什么？

<details><summary>答案与出处</summary>

生产者 warp 用 TMA 把 $A$、$B$ 的块搬进共享内存的环形缓冲；每一格有 full 和 empty 两个 mbarrier，分别表示"数据到齐"和"用完可覆盖"；消费者 warpgroup 等 full、发起 wgmma，等 MMA 完成后到达 empty（24.1–24.4 节、命题 24.5）。最常见的错误是在**发起**异步 MMA 之后就释放它读的格：MMA 还没读操作数，生产者已经开始覆盖（例 24.4、习题 24.2）。持久化 kernel 循环领取输出块，Stream-K 解决尾波（24.6 节）。

</details>

**6.** FlashAttention 为什么快？FlashAttention-2、3、4 各改进了什么？

<details><summary>答案与出处</summary>

用在线 softmax 一块块处理键值，$T \times T$ 的矩阵不进 HBM，softmax 也不再单独读写（10.2 节、注 27.2）。FA2：按查询行分给 warp，行归约在 warp 内完成（27.2 节）。FA3：Hopper 上 warp 专门化与 warpgroup 乒乓，让 softmax 与矩阵乘法重叠，支持 FP8。FA4：Blackwell 上指数单元成为瓶颈（命题 27.4），部分指数改用多项式近似，并减少重新缩放（27.4 节）。

</details>

**7.** 长上下文、小批量的 decode 为什么跑不满 GPU？怎么办？

<details><summary>答案与出处</summary>

任务数（批量 × 键值头）远少于 SM 数，每个任务又要读很长的 KV（例 27.7）。沿键值方向切分（split-KV）：每段算出部分状态，再按命题 10.6 合并；合并的是状态，不能对各段的输出取平均（习题 27.8、例 27.9）。切分方式若随批量变化，就不再批不变（注 27.12）。

</details>

**8.** DeepSeek-V3 的 FP8 训练怎样处理精度问题？

<details><summary>答案与出处</summary>

细粒度的块缩放：激活按 $1 \times 128$、权重按 $128 \times 128$ 的块缩放，离群值只影响自己的块（命题 26.2）；发现 Tensor Core 内部的 FP8 累加只有约 14 位有效数字，于是每累加 128 个元素就把部分和提升到 f32，在 CUDA 核心上累加，相当于把命题 2.20 中的 $n$ 换成了段长（26.2 节、例 26.4）。

</details>

**9.** 批量为 1 的 decode，为什么一次前向被拆成约一百个 kernel 会慢？megakernel 怎样解决，又引入了什么新代价？

<details><summary>答案与出处</summary>

每个 kernel 边界有启动（约 1–2 µs）、尾波（最后一轮 SM 空闲）和流水线重新起步三笔损失，小模型时可占四成以上（例 24.13）。megakernel 让每个 SM 执行事先排好的指令表，共享内存分页在指令之间流转，依赖用显存计数器的释放/获取表达（24.8 节）。新代价是 SM 之间每次交接都要经过几次显存延迟，B200 上约占总时间的四成（例 24.14）。

</details>

**10.** 张量并行的通信和 GEMM 怎样重叠？切得越细越好吗？

<details><summary>答案与出处</summary>

把输出切成 $c$ 块，算完一块就发起它的通信。总时间约为 $\max(t_m + t_c/c + \alpha,\ t_c + c\alpha + t_m/c)$：切太粗，首尾露在外面；切太细，固定开销 $c\alpha$ 累积（命题 28.4、例 28.5）。在 GPU 上还要算通信 kernel 对 SM 的占用（28.1 节）。

</details>

**11.** 一个多 GPU 训练程序只在出现 NaN 的 GPU 上多调用一次 all-reduce 来同步错误标志，会怎样？

<details><summary>答案与出处</summary>

其余 GPU 没有调用，出错的 GPU 一直等待（死锁），或者与下一次集合操作错配。所有参与者必须以相同的次序调用相同的集合操作；应当每一步都无条件地对错误标志做 all-reduce（28.5 节、习题 28.4）。

</details>

**12.** AI 交回一个 kernel，声称比 PyTorch 快 20 倍。你要检查什么？

<details><summary>答案与出处</summary>

正确性检查是否独立于被测代码，输入是否覆盖特殊值、边界形状和几种不同的分布；计时边界是否明确、是否同步到 kernel 跑完；基线是否合理；用屋顶线检查这个加速是否可能（25.7 节、例 25.8、注 25.9，附录 C 的 C.9 节）。Sakana AI 的例子说明，十倍以上的"加速"可能只是钻了评测的空子。

</details>

**13.** 写一份交给 AI 的 GPU kernel 规格，至少要包含哪几项？

<details><summary>答案与出处</summary>

数学定义（含掩码、缩放、边界情形）、形状与类型、布局、分块与遍历次序、数据移动与流水线级数、同步关系（每格的到达字节数与完成身份）、数值要求、按屋顶线算出的性能目标、验证方式（附录 C 的 C.2 节；GPU 的例子见例 26.11 与 C.7 节）。

</details>
