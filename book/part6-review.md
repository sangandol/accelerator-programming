# 第六部分　回顾与自测

第六部分是两条路线的汇合处，讲 kernel 之上的那一层：一个模型的文件里有什么，提示怎样变成词元、输出怎样抽样；近年的模型怎样改造注意力来压缩 KV cache；推理引擎每一步怎样调度、怎样把 CPU 的开销藏起来；KV cache 怎样作为一个存储系统来复用；几百块 GPU 怎样分工服务一个模型。正文只依赖第一、二部分。读完这一部分，就能看懂 vLLM、SGLang、DeepInfer 这类引擎的结构，并为一个部署估算容量、延迟、带宽和成本。

## 这一部分的骨架

1. 检查点是名字到（类型、形状、字节）的表；存储按全部参数算，运算按每词元实际用到的参数算；抽样时 top-k 与温度可交换，top-p 不可交换。（定义 29.1、命题 29.2、定义 29.16）
2. 缓存的账分三个乘数：每项的大小、序列方向的项数、每步读多少项；各种注意力变体各改其中一个，稀疏选择不省存储，跨层共享不省读取。（定义 30.1、例 30.2）
3. 一步的输入是摊平的一行词元；除注意力之外的运算都逐词元；异步调度把每步用时从 $T_g + T_c$ 降到 $\max(T_g, T_c)$。（定义 31.2、命题 31.3、31.11）
4. 前缀缓存按整页建索引，键是链式哈希；从存储读回缓存划算，当且仅当带宽超过持平带宽。（命题 32.4、32.8）
5. 宽专家并行让每个专家分到更多词元，强度与卡数成正比；最慢的一块决定整步，所以要负载均衡与双重路由。（命题 33.1、33.2）

**最常用的节。** 29.1、29.2、29.4 节；30.1、30.2、30.5 节和例 30.15；31.3–31.5、31.7 节；32.2、32.3 节；33.1–33.3、33.5 节。面试里"讲讲 vLLM 是怎么工作的""怎样估算一个推理部署要多少卡"这类问题，答案都在这一部分。

**这时可以读的附录。** 附录 A 的 A.7 节（主机链路、网络与存储）与附录 B 的 B.9 节（推理引擎的参数与名词）；附录 F 的论文导读里，DeepInfer 与 DeepSeek-V4.1-Flash 一条对应这一部分。

## 自测题

**1.** 用户在聊天窗口按下回车之后，到第一个字出现之前，服务器端依次发生了什么？

<details><summary>答案与出处</summary>

接入层按对话模板把消息排成带特殊词元的提示、编码成词元编号（29.2 节）；匹配前缀缓存，算出命中长度（32.2 节），按负载把请求路由到某个 prefill 实例（33.4 节）；调度器在某一步把它的未命中部分（可能分段）排进批里，分配页，准备摊平的输入、经锁页内存搬上设备（31.2–31.4 节）；前向写入缓存，只对最后一个位置算 logits，在设备上抽样（例 29.15、31.6 节）；若 prefill 与 decode 分离，缓存逐层交给 decode 实例（32.4 节）；词元编号搬回 CPU，流式解码时扣下不完整的字符和可能的停止串，按事件流发回（命题 29.8、29.24）。首词元时间就是这一串的总和（定义 31.13）。

</details>

**2.** 下载一个模型，拿到的是什么？怎样从 `config.json` 估算它占多少显存、每个词元算多少？

<details><summary>答案与出处</summary>

权重（名字 → 类型、形状、行优先字节的检查点，safetensors 是 8 字节长度加 JSON 文件头加原始字节）、结构（配置加代码）、词表（定义 29.1）。量化张量的字节数为 $n(b/8 + c/g)$，打包使文件里的形状与逻辑形状不同（命题 29.2）。存储按全部参数算，运算按每词元实际用到的参数算；DeepSeek-V4.1-Flash 约 510 GB，decode 时每词元约 160 亿参数（例 29.3）。

</details>

**3.** 温度、top-k、top-p 各是什么？顺序重要吗？怎样让抽样可以重放？

<details><summary>答案与出处</summary>

定义 29.16。top-k 只看名次，与温度可交换；top-p 看累计概率，不可交换（例 29.17）。随机数应只由（种子、位置、用途）决定，不由批内行号决定；用定点数的前缀和做逆分布函数抽样，结果与分块方式无关（命题 29.19）；前向本身也要批不变（11.12 节）。

</details>

**4.** MLA 为什么能只缓存一个潜向量？它对 decode 的强度和并行方式有什么影响？

<details><summary>答案与出处</summary>

还原键值的矩阵可以并进查询和输出投影（命题 30.4），decode 时是所有头共用一个 $d_c$ 维键值头的 MQA；RoPE 要另分出一小段共享的键。强度约 $4H/s$，接近计算受限（命题 30.5）。按头切分不能切开潜向量，缓存会被复制，所以注意力用数据并行（命题 30.6）。

</details>

**5.** 稀疏注意力省的是什么？不省什么？线性注意力呢？

<details><summary>答案与出处</summary>

稀疏选择省主注意力的读取和计算，不省存储，索引器仍随上下文线性增长，长上下文时成了大头（命题 30.12、例 30.13）。线性注意力把缓存换成 $d_k \times d_v$ 的状态，与长度无关，但短序列时状态可能比 KV cache 还大（例 30.17）；投机解码的回退和从中间续算都要快照（30.6 节）。账要分三项算：存多少、每步读多少、每步算多少（定义 30.1）。

</details>

**6.** 连续批处理时，一步的输入长什么样？推理引擎怎样把 CPU 的开销藏起来？

<details><summary>答案与出处</summary>

所有请求的词元摊平成一行：词元、位置、起点、长度、页表、写入槽号、抽样的行；除注意力外都逐词元，不必填充（定义 31.2、命题 31.3）。每步几百次 kernel 发起用录制消除，批量补齐到档位（命题 31.8）；异步调度让 CPU 提前一步调度、落后一步处理输出，每步用时从 $T_g + T_c$ 降到 $\max(T_g, T_c)$（命题 31.11）。

</details>

**7.** 前缀缓存怎样认出相同的前缀？什么时候从 SSD 读回缓存比重算划算？

<details><summary>答案与出处</summary>

只对整页建索引，键是链式哈希 $h_j = H(h_{j-1}, \text{第 } j \text{ 页})$，因为一页的缓存依赖它前面的全部词元（命题 32.4）；淘汰只淘汰链的末端（命题 32.6）。读回划算当且仅当带宽超过持平带宽 $ePu/F$：稠密 GQA 模型约几 GB/s，DeepSeek-V4.1-Flash 只有几十 MB/s（命题 32.8、例 32.9）。缓存越小，越能按天保存（命题 32.10）。

</details>

**8.** 为什么 DeepSeek 的 decode 要用 64 到 128 块 GPU 的专家并行？会带来什么问题？

<details><summary>答案与出处</summary>

每块 GPU 每步的词元数受单用户速度限制；专家并行越宽，每个专家分到的词元越多（$pnk/E$），每块 GPU 读的专家权重越少，强度与 $p$ 成正比（命题 33.2、例 33.3）。问题：全交换要求高带宽的交换域（例 12.15）；最慢的一块决定整步，需要专家负载均衡和按请求数与上下文长度双重路由（命题 33.1、33.8，33.3 节）；整个实例是一个故障域（例 33.12）。

</details>
