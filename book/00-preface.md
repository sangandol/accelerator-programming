# 前言

## 这本书讲什么

今天的深度学习计算几乎都跑在两类加速器上：Google 的 TPU 和 NVIDIA 的 GPU。本书的目标是让读者尽快掌握为它们编程的整套体系：芯片里有什么、为什么这样设计、程序怎样把计算安排上去、怎样判断一个程序是否已经接近机器的上限。

全书自底向上，像一本数学书那样线性展开：每个概念先定义、后使用，每一章只建立在前面的章之上。

- **第一部分　硬件**：从逻辑门出发，依次建立加法器、乘法器与浮点运算、存储、流水线与控制、矩阵单元，再把它们组装成一颗芯片和一组用互联连接的芯片。每一层都回答同一个问题：这一层能做什么，各要付出多少面积、时间和能量。
- **第二部分　计算的共同结构**：在这样的机器上组织计算时，两类加速器共有的问题：数组怎样摆放在存储中（布局）、搬运与计算怎样重叠（异步与流水线）、归约类计算怎样并行、Transformer 各部分的计算量和数据量、多设备之间怎样分工。
- **第三部分　JAX**：JAX 的计算模型和分布式编程。
- **第四部分　TPU** 与 **第五部分　GPU**：两条独立的路线，各自讲机器的结构、编程模型（Pallas；CUDA 与 tile 语言）、矩阵乘法与注意力等典型 kernel，以及多芯片编程。

为什么从逻辑门开始？因为加速器上几乎每一条性能规律，追到底都是电路层面的事实。乘法器的面积随位数的平方增长，所以加速器偏爱低精度格式；把数据从远处搬来比在近处计算贵得多，所以程序的首要任务是让数据被反复使用；超前进位加法器把串行的进位链变成对数深度的树，同一个方法以后用来做并行归约和多芯片之间的 all-reduce。从底层往上走，后面的规律都有来历，记起来也快。

但底层只讲上层用得到的部分。逻辑门一章不讲晶体管和工艺；存储一章不讲 DRAM 的刷新电路。每章末尾的**接口小结**列出上层会用到的结论，这是本书最重要的阅读工具：读者可以先只读一章的定义、定理陈述和接口小结，把实现细节留到需要时再回来看，就像使用一个定理而暂时不读它的证明。

本书**不讲**：工具链的安装和配置、构建系统、调试器的用法、API 的完整参数表，以及与加速器编程无关的深度学习知识。现在大部分代码由 AI 来写，这些都可以交给 AI 或官方文档。本书也**不要求做实验**：结论靠推导得出；需要的硬件数字取自公开资料，集中列在[附录 A](A-hardware.md)。

## 读者

假定读者：

- 熟悉线性代数、基本的离散数学和概率，能读证明；
- 了解基本的计算机体系结构：寄存器、缓存、内存、指令的概念；
- 能读懂简单的 Python 代码。

不假定读者用过 JAX、PyTorch、CUDA，也不假定读者了解神经网络的细节；第 11 章会把需要的 Transformer 知识写成算术。

## 怎样读得快

1. **先读骨架。** 每章先读开头的"在体系中的位置"、各个定义、定理和命题的陈述、例子，以及章末的接口小结。证明和较长的推导初读可以跳过。
2. **做核心习题。** ★ 标记的习题检验的是上层要用的内容。做不出来时打开提示，提示是逐级给出的，依次读完通常就能写出答案。
3. **卡住时往下查。** 读到上层某个结论不明白时，顺着它注明的出处回到下层对应的定理，这时再读证明。
4. **数字看量级。** 书中的硬件数字只需记住量级（几十还是几千个周期，几百 GB/s 还是几 TB/s），精确值随时可以查附录 A。

## 体例

每章的结构是：开头一两段说明本章回答的问题，接着是"在体系中的位置"框，然后是正文各节，最后是接口小结和习题。

每章内的定义、命题、定理、引理、推论、例和注共用一个编号，例如定义 3.1、命题 3.2、例 3.3，便于查找；习题单独编号。证明以"*证明*"开头，以 ∎ 结尾。

**习题**放在每章末尾。★ 标记核心习题，☆ 标记可以跳过的习题。每道题后面有折叠起来的提示和答案。有一类习题叫**审查题**：给出一段代码，假想它由 AI 写出，要求找出其中的错误或性能问题。这是本书读者在实际工作中最常做的事。

**现状框**：凡是随时间变化的内容（某一代芯片的参数、某个 API 的写法、某一代特有的指令），都写在这样的框里，并注明日期：

> **现状（2026-10）**：例如，NVIDIA 当前最新的数据中心 GPU 架构是 Rubin，Google 当前最新的 TPU 是第八代的 TPU 8t 与 TPU 8i。

正文中的定理和推导不依赖现状框中的数字。几年后这些数字过时，只需更新现状框和附录 A、B。

## 记号

- $[n] = \{0, 1, \dots, n-1\}$。下标一律从 0 开始，与代码一致。
- 数组 $A \in \mathbb{R}^{M \times K}$ 的元素写作 $A[i, k]$；切片 $A[i_0{:}i_1, :]$ 是左闭右开的区间，与 Python 相同。
- $\lceil x \rceil$、$\lfloor x \rfloor$ 是上下取整，$a \bmod b$ 是非负余数，$\log$ 默认以 2 为底。
- 矩阵乘法总写作 $C = AB$，$A \in \mathbb{R}^{M \times K}$，$B \in \mathbb{R}^{K \times N}$，$C \in \mathbb{R}^{M \times N}$：$M$ 是结果的行数，$N$ 是结果的列数，$K$ 是被求和消去的维度。分块大小写作 $b_M, b_N, b_K$。
- 一次乘加（multiply-add）计为 2 次浮点运算（FLOP），所以上面的矩阵乘法是 $2MNK$ FLOPs。
- 数据类型的字节数写作 $s$：$s_{\text{f32}} = 4$，$s_{\text{bf16}} = 2$，$s_{\text{fp8}} = 1$，$s_{\text{fp4}} = 1/2$。
- 容量用二进制单位：$1\,\text{KiB} = 2^{10}$ 字节，$1\,\text{MiB} = 2^{20}$ 字节。带宽和算力沿用厂商的十进制单位：$1\,\text{GB/s} = 10^9$ 字节/秒，$1\,\text{TFLOP/s} = 10^{12}$ FLOP/秒。
- 算力峰值记作 $P$（FLOP/s），带宽记作 $B$（字节/秒），延迟记作 $L$（秒或周期）。

代码块中，Python 代码使用 JAX 的 `jax.numpy`（记作 `jnp`），它的写法与 NumPy 基本相同。第 13 章之前出现的代码只用到这一部分，可以当作可执行的数学记号来读。

## 与 AI 合作

本书默认读者让 AI 写代码，自己负责三件事：把需求写成精确的规格（形状、数据类型、布局、分块、分片、同步关系），估出这个计算最快能多快，再审查 AI 写出的代码是否正确、是否接近这个上限。书中的定理几乎都可以直接变成一条规格或一条审查要点，例如：

- 规格："K 方向的分块大小 $b_K$ 取 512，累加器用 f32，放在片上内存中，在 K 循环结束后写回一次"；
- 估算："这个矩阵乘法的算术强度是 300 FLOP/字节，高于这台机器的屋顶线拐点，应当是计算受限的，理想时间约 2 ms"；
- 审查："这个双缓冲在发起下一次拷贝之前没有等待上一次读取完成，第二轮会覆盖正在使用的缓冲"。

[附录 C](C-ai-workflow.md) 把这些整理成规格模板和审查清单。
