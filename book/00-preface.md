# 前言

## 这本书讲什么

今天的深度学习计算几乎都跑在两类加速器上：Google 的 TPU 和 NVIDIA 的 GPU。这本书想让你尽快掌握为它们编程的整套体系：芯片里有什么，为什么这样设计，程序怎样把计算安排上去，怎样判断一个程序是否已经接近机器的上限。

全书自底向上，像一本数学书那样线性展开：每个概念先定义、后使用，每一章只建立在前面的章之上。

- **第一部分　硬件**：从逻辑门出发，依次搭起加法器、乘法器与浮点运算、存储、流水线与控制、矩阵单元，再把它们组装成一颗芯片和一组用互联连接的芯片。每一层都问同一个问题：这一层能做什么，各要付出多少面积、时间和能量。
- **第二部分　计算的共同结构**：在这样的机器上组织计算时，两类加速器共有的问题：数组怎样摆放在存储中（布局），搬运与计算怎样重叠（异步与流水线），归约类的计算怎样并行，Transformer 各部分的计算量和数据量，多个设备之间怎样分工。
- **第三部分　JAX**：JAX 的计算模型和分布式编程。
- **第四部分　TPU** 与 **第五部分　GPU**：两条独立的路线，各自讲机器的结构，编程模型（Pallas；CUDA 与 tile 语言），矩阵乘法与注意力等典型 kernel，以及多芯片编程。第四部分的最后一章是一个完整的研究案例：把一篇 2026 年的论文从问题、正确性定义、性能分析一直讲到编译器，示范一次性能研究是怎样做的。
- **第六部分　大模型推理系统**：两条路线在这里汇合，讲 kernel 之上的那一层。一个模型的文件里有什么，文本怎样变成词元、输出怎样抽样；近年的模型怎样改造注意力来压缩 KV cache；推理引擎怎样调度一步、怎样把 CPU 的开销藏起来；KV cache 怎样作为一个存储系统来复用；几百块 GPU 怎样分工服务一个模型。以 DeepSeek 在 2026 年 10 月开源的推理框架 DeepInfer 为贯穿的实例。

- **第七部分　模型调用与智能体编排**：在推理服务之上，讲应用怎样使用模型。以"自动估算一个模型能否放进一块卡"为贯穿的任务：一次调用的输入、输出和账；工具、检索与记忆；多个 agent 的依赖、并发与容量；领取、恢复、副作用、权限与验收；最后以 ARTEX 的固定社区源码快照为案例，把这些机制落实到函数和存储状态。

书中还收入了 2025–2026 年的一批论文，都讲到能读懂原文的程度：推理服务为什么温度为 0 也会给出不同的回答（批不变性），投机解码，DeepSeek 关于模型与硬件协同设计的分析，Google 在 TPU 上的推理注意力 kernel，FlashInfer，把整个模型写成一个 kernel 的 megakernel，以及 DeepSeek-V4.1-Flash 的技术报告和 DeepInfer 的部署说明。它们分散在用得上的章节里，附录 F 有一份导读。

为什么从逻辑门开始？因为加速器上几乎每一条性能规律，追到底都是电路层面的事实。乘法器的面积随位数的平方增长，所以加速器偏爱低精度格式；把数据从远处搬来比在近处计算贵得多，所以程序的首要任务是让数据被反复使用；超前进位加法器把串行的进位链变成对数深度的树，同一个办法后来又用在并行归约和多芯片之间的 all-reduce 上。从底层往上走，后面的规律都有来历，记起来也快。

但底层只讲上层用得到的部分。逻辑门一章不讲晶体管和工艺，存储一章不讲 DRAM 的刷新电路。每章末尾的**本章小结**列出后面会用到的结论，并注明出处。读者可以先只读一章的定义、定理陈述、例子和本章小结，把证明留到需要时再回来看，就像先使用一个定理、暂时不读它的证明。

本书**不讲**：工具链的安装和配置、构建系统、调试器的用法、API 的完整参数表，以及与加速器编程无关的深度学习知识。现在大部分代码由 AI 来写，这些都可以交给 AI 或官方文档。读者也**不需要做实验**：结论靠推导得出，书像数学书一样读。书中会介绍别人做过的实验和测量（论文、厂商资料、公开测评），注明来源与日期，用来印证推导，或者让你知道现实中的数字是多少；需要的硬件参数集中列在[附录 A](A-hardware.md)。

## 读者

假定读者：

- 习惯读数学书、能读证明；线性代数、概率和微积分学过即可，用到的工具书中都会补齐（见下文的间章）；
- 了解基本的计算机体系结构：寄存器、缓存、内存、指令的概念；
- 能读懂简单的 Python 代码。

不假定读者用过 JAX、PyTorch、CUDA，也不假定读者了解神经网络的细节；第 11 章从"语言模型在算什么"讲起，把需要的 Transformer 知识写成算术，并讲清训练在算什么（损失、梯度下降、优化器），第 29 章再讲一个模型从文件、词元到抽样的全貌。

书中用到的数学工具，凡是超出大学一年级的，都在**间章**里讲清楚：间章 M1（对数、求和、归纳与大 O 记号）放在第 1 章之前，M2（几个不等式）在第 6 章之前，M3（线性代数：映射、核与比特向量）在第 8 章之前，M4（概率）与 M5（导数、梯度与链式法则）在第 11 章之前。每个间章都放在第一次用到它的那一章前面，配有例子和习题；熟悉的读者可以跳过，用到时再回来查。间章里的条目编号写作"定义 M3.9"这样的形式。

## 怎样读得快

1. **先读骨架。** 每章先读开头的几段、各个定义和命题的陈述、例子，以及章末的本章小结。证明和较长的推导初读可以跳过。
2. **做核心习题。** ★ 标记的习题检验的是后面要用的内容。先自己算，算不下去就打开答案对照过程：答案写出了每一步用的公式和代入的数，照着走一遍和自己做出来差不多。
3. **卡住时往回查。** 读到某个结论不明白时，顺着它注明的出处回到前面对应的定理，这时再读证明。
4. **数字看量级。** 书中的硬件数字只需记住量级（几十还是几千个周期，几百 GB/s 还是几 TB/s），精确值随时可以查附录 A。
5. **读完一部分就自测。** 每一部分末尾有一页"回顾与自测"：这一部分的骨架、面试和写规格时最常用的节、这时可以读哪些附录，以及一组注明出处的自测题。答不上来的，回到出处去读。读完一条路线之后，再看[附录 F](F-interview.md) 的近期论文导读。

## 体例

每章的开头用几段话交代这一章讲什么、为什么需要、和前面哪几章接上；然后是正文各节；最后是本章小结和习题。

每章内的定义、命题、定理、引理、推论、例和注共用一个编号，例如第 3 章依次是定义 3.1、命题 3.2、定义 3.3、例 3.4，便于查找；习题和插图各自单独编号。它们的陈述单独成段，左边有一条竖线（在 GitHub 上显示为引用块）；证明以"*证明*"开头，以 ∎ 结尾，写在竖线之外。

用本地阅读器读时，顶栏有几个辅助：**大纲**列出本章的节与编号条目，**术语**列出本章的术语与英文，**折叠证明**只留下陈述（第 1 条读法），**英文**在术语后显示英文名，**版式**可以调整字体、字号、行宽、行距和背景。正文中的编号引用与术语，鼠标停在上面就能看到原文。

**习题**放在每章末尾。★ 标记核心习题，☆ 标记可以跳过的习题。每道题后面有折叠起来的答案；少数需要找入手点的题另有一个提示，给出第一步该怎么走。有一类习题叫**审查题**：给出一段代码，假想它由 AI 写出，要求找出其中的错误或性能问题。这是本书读者在实际工作中最常做的事。

**现状框**：凡是随时间变化的内容（某一代芯片的参数、某个 API 的写法、某一代特有的指令、论文里的测量数字），都写在这样的框里，并注明日期：

> **现状（2026-10）**：例如，NVIDIA 当前最新的数据中心 GPU 架构是 Rubin，Google 当前最新的 TPU 是第八代的 TPU 8t 与 TPU 8i。

正文中的定理和推导不依赖现状框中的数字。几年后这些数字过时，只需更新现状框和附录 A、B。

## 记号

- $[n] = \{0, 1, \dots, n-1\}$。下标一律从 0 开始，与代码一致。
- 数组 $A \in \mathbb{R}^{M \times K}$ 的元素写作 $A[i, k]$；切片 $A[i_0{:}i_1, :]$ 是左闭右开的区间，与 Python 相同。
- $\lceil x \rceil$、$\lfloor x \rfloor$ 是上下取整，$a \bmod b$ 是非负余数，$\log$ 默认以 2 为底，$\ln$ 是自然对数；$O$、$\Omega$、$\Theta$ 是渐近记号。它们的用法见间章 M1。
- 矩阵乘法总写作 $C = AB$，$A \in \mathbb{R}^{M \times K}$，$B \in \mathbb{R}^{K \times N}$，$C \in \mathbb{R}^{M \times N}$：$M$ 是结果的行数，$N$ 是结果的列数，$K$ 是被求和消去的维度。分块大小写作 $b_M, b_N, b_K$。
- 一次乘加（multiply-add）计为 2 次浮点运算（FLOP），所以上面的矩阵乘法是 $2MNK$ FLOPs。
- 数据类型的字节数写作 $s$：$s_{\text{f32}} = 4$，$s_{\text{bf16}} = 2$，$s_{\text{fp8}} = 1$，$s_{\text{fp4}} = 1/2$。
- 容量用二进制单位：$1\,\text{KiB} = 2^{10}$ 字节，$1\,\text{MiB} = 2^{20}$ 字节。带宽和算力沿用厂商的十进制单位：$1\,\text{GB/s} = 10^9$ 字节/秒，$1\,\text{TFLOP/s} = 10^{12}$ FLOP/秒。
- 算力峰值记作 $P$（FLOP/s），带宽记作 $B$（字节/秒），延迟记作 $L$（秒或周期）。

代码块中，Python 代码使用 JAX 的 `jax.numpy`（记作 `jnp`），它的写法与 NumPy 基本相同。第 13 章之前出现的代码只用到这一部分，可以当作可执行的数学记号来读。

书中的代码怎样验证过：JAX 与 Pallas 的代码在 CPU 上用 JAX 0.11.2 运行过，Pallas kernel 用 TPU 解释器运行（开启竞争检测），多设备的代码用模拟的 8 个设备运行；解释器不检查 TPU 的布局约束，只能在真机上运行的功能没有验证。CUDA C++、Triton、cuTile 的代码在写作时没有可用的 CUDA 工具链，只做了人工推理，所以都写成短小、标准的形式。

## 与 AI 合作

本书默认读者让 AI 写代码，自己负责三件事：把需求写成精确的规格（形状、数据类型、布局、分块、分片、同步关系），估出这个计算最快能多快，再审查 AI 写出的代码是否正确、是否接近这个上限。书中的定理几乎都可以直接变成一条规格或一条审查要点，例如：

- 规格："K 方向的分块大小 $b_K$ 取 512，累加器用 f32，放在片上内存中，在 K 循环结束后写回一次"；
- 估算："这个矩阵乘法的算术强度是 300 FLOP/字节，高于这台机器的屋顶线拐点，应当是计算受限的，理想时间约 2 ms"；
- 审查："这个双缓冲在发起下一次拷贝之前没有等待上一次读取完成，第二轮会覆盖正在使用的缓冲"。

[附录 C](C-ai-workflow.md) 把这些整理成规格模板和审查清单（每一部分末尾的回顾页会说明，读到那里时附录 C 的哪几节已经能用了），并用几项公开的研究说明为什么 AI 写的 kernel 必须经过独立的正确性检查和严格的计时。
